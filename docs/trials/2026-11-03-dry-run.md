## 目的と方法
- この設定が実際に回るか、また止まるべきところで止まるかを確かめる。
- 依存の追加や有料 API は使わない。このリポジトリとは別の、使い捨てのサンドボックス用 git リポジトリで実施した（コンテナ内の一時領域。push していない）。
  - 中身はこのリポジトリの設定（コミット f58f8e0 時点）の複製と、Python の小さな関数 1 つだけ。
  - 検証用の関数: `tax_included(price, rate_percent=10)`。既存実装は `round(price * (100 + rate_percent) / 100)` で、105 → 116（本来は切り捨てで 115）、負の値も通ってしまう。
  - サンドボックスの `scripts/check.config`:
    - lint: `python3 -m compileall -q src tests`（構文チェックのみ）
    - typecheck: `mypy --strict src`（環境にもともとある）
    - test: `python3 -m unittest discover -s tests -t . -v`
- 統括役はメインセッション（このセッション）。implementer / reviewer / verifier は Claude Code のサブエージェントとして起動した。

## 試行で見つかり、このPRで直したこと
1. **定義の変更はセッションを開き直すまで反映されない。** サブエージェントの定義と CLAUDE.md はセッション開始時に読み込まれる。そのため 1 回目の implementer は古い手順に従い、範囲外の引き継ぎ記録を書いた。これは今回のレビュー指摘 1 の矛盾そのものだった。
   → `docs/team-blueprint.md` に「設定を変えたら新しいセッションで」と追記。試行の 2 回目以降は、各エージェントに更新版のファイルを明示的に読ませて実施した。
2. **reviewer が範囲外の変更を PASS にした。** → `.claude/agents/reviewer.md` で、範囲外の変更・テストの弱体化・秘密情報は必ず MUST_FIX にするよう明記。
3. **verifier が `| tail` を挟んだため、main の終了コードを取れなかった。** → `.claude/agents/verifier.md` に、終了コードはパイプを通さずに取るよう明記。
4. **フックの誤検知。** 統括役（このセッション）のコマンドも、コミットメッセージや置換テキストに「rm -rf」「find -delete」という文字列を含むだけで止まった。→ `docs/safety-boundaries.md` に記載。回避策は、メッセージをファイルに書いてから渡すこと。
